# Расписание АПТ

Личный сайт расписания Альметьевского политехнического техникума.
Данные берутся напрямую с официального сайта **almetpt.ru** и отдаются
в красивом интерфейсе: выбор курса и группы, день недели, живой статус
текущей пары, замены, темы и домашние задания, время пар и перемены.

## Возможности

- **Выбор курса → группы → дня** (курсы I–IV, 82 группы, поиск по названию)
- Расписание на любой день: пары с временем начала/конца, длительностью,
  аудиторией (или on-line), преподавателем, темой и домашним заданием
- Время всех пар: I 08:00–09:20 … VIII 18:40–20:00
- Живой режим: текущая пара подсвечена, есть прогресс-бар и обратный отсчёт,
  панель «что сейчас», перемены и «окна» между парами
- Пометка **замен** (пары, отличающиеся от основного расписания)
- Бонус: «Консультации преподавателей» и «График учебного процесса на год»
- Светлая/тёмная тема (авто по системе), запоминание группы и темы
- Ссылки вида `#/1042/2026-10-02` — можно отправлять другу, кнопка «поделиться»
- Свайпы влево/вправо и стрелки клавиатуры — смена дня
- Автообновление расписания каждые 10 минут, кнопка ручного обновления
- Анимации: пружинные переходы, постепенное появление карточек, скелетоны

## Архитектура

```
apt-schedule/
├── server.py            # HTTP-сервер (только стандартная библиотека Python)
├── parser.py            # мини-DOM + парсеры страниц almetpt.ru
├── static/index.html    # весь фронтенд (дизайн, логика, анимации)
└── data/
    ├── groups.json      # эталонный список групп (fallback без сети)
    ├── bells.json       # время пар (fallback)
    └── cache/           # дисковый кэш расписаний по дням
```

Бэкенд выступает «живым» парсером-прокси: фронтенд запрашивает
`/api/...`, сервер забирает страницы с almetpt.ru, превращает их в чистый
JSON и кэширует (группы — 6 ч, расписание дня — 10 мин). При недоступности
сайта отдаётся последняя сохранённая копия.

### API

| Метод | Ответ |
|---|---|
| `GET /api/groups` | `{ ok, groups:[{id,name,course}], fetchedAt, source }` |
| `GET /api/schedule?group=ID&date=YYYY-MM-DD` | `{ ok, pairs:[…], published, consultations, graf, … }` |
| `GET /api/bells` | время пар |
| `GET /api/health` | проверка живости |

Поле `pairs[]`: `n` (римский номер), `start`/`end` (HH:MM), `room`,
`roomTitle`, `subject`, `subjectFull`, `teacher`, `topics[]`, `homework[]`,
`changed` (замена), `subgroup`, `variants`.

## Запуск

```bash
python3 server.py          # http://localhost:8000
PORT=8080 python3 server.py
```

Зависимостей нет — нужен только Python 3.9+ и доступ к almetpt.ru.

## Деплой

Подходит любой хостинг, где может работать Python:

- **VPS**: `nohup python3 server.py &` или systemd-unit, плюс nginx/Caddy
  с проксированием на порт 8000
- **Docker**: базовый образ `python:3-slim`, `CMD ["python3", "server.py"]`
- **PythonAnywhere / PaaS**: запуск `server.py` как веб-приложения

Переменная окружения `PORT` задаёт порт.

## Деплой на GitHub (бесплатно, без сервера)

Сайт умеет работать полностью статически: бот на **GitHub Actions**
собирает расписание в JSON-файлы, а **GitHub Pages** их раздаёт.
Фронтенд сам определяет, где он запущен: есть `api/health` — работает
с живым сервером, нет — читает статические файлы `data/`.

Структура репозитория (папка `apt-schedule` — это корень репо):

```
├── server.py, parser.py, static/   # для живого режима
├── fetch_all.py                    # бот: almetpt.ru -> docs/data/*.json
├── docs/                           # то, что раздаёт GitHub Pages
│   ├── index.html                  # копия фронтенда (бот обновляет сам)
│   └── data/
│       ├── groups.json, bells.json, meta.json
│       └── d/<groupId>/<date>.json # расписание на даты -1 .. +3 дня
└── .github/workflows/update.yml    # cron: каждые 30 минут
```

### Как включить

1. Создай приватный или публичный репозиторий и запушь эту папку:
   ```bash
   git init && git add -A && git commit -m "init"
   git branch -M main
   git remote add origin git@github.com:<you>/<repo>.git
   git push -u origin main
   ```
2. **Settings → Pages → Build and deployment**: `Deploy from a branch`,
   ветка `main`, папка `/docs` → Save.
3. Вкладка **Actions** — разрешить workflows, если спросит. Первый запуск
   случится по расписанию, но его можно стартовать вручную:
   `Actions → Обновление расписания (бот) → Run workflow`.
4. Через минуту сайт будет на `https://<you>.github.io/<repo>/`.

### Как это работает

- `update.yml` по cron `12,42 * * * *` (каждые ~30 мин) запускает
  `fetch_all.py`: он скачивает группы, звонки и расписание всех 82 групп
  на даты от вчера до +3 дней (по МСК, воскресенья пропускаются —
  это ~330 страниц меньше чем за 2 минуты) и коммитит изменения в `docs/`.
- Файлы младше 25 минут не перезапрашиваются — повторный прогон почти мгновенный.
- Просроченные файлы старше недели бот удаляет сам.
- Если сайт техникума недоступен — бот просто оставляет старые данные,
  зеркало не ломается.
- Коммитит бот только когда данные реально изменились.

### Нюансы

- **Cron в Actions не точный**: на бесплатных раннерах запуски могут
  опаздывать на 5–30 минут. Для расписания этого хватает с запасом.
- Запросы идут из дата-центров GitHub (не из РФ). Если almetpt.ru вдруг
  начнёт резать иностранные IP, лечится self-hosted раннером или
  переездом на живой `server.py` (он тянет данные на лету).
- Даты вне диапазона `-1 .. +3` на статическом зеркале показывают
  заглушку «за эту дату данных нет» — это ожидаемо.
- 200 бесплатных минут Actions в месяц для приватных репо хватает
  (~2 мин × 48 прогонов/день ≈ 100 мин/мес). Публичный репозиторий —
  минуты бесплатны без лимита.
