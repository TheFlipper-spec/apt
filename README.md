# Расписание АПТ

Личный сайт расписания Альметьевского политехнического техникума.
Данные берутся с официального сайта **almetpt.ru** и показываются в нормальном
интерфейсе: выбор курса и группы, живой статус текущей пары, замены, темы,
домашние задания, перемены, поиск по преподавателям и экспорт в календарь.

Работает в двух режимах и сам понимает, в каком запущен:

| Режим | Что это | Данные |
|---|---|---|
| **Статический** | GitHub Pages, папка `docs/` | JSON-файлы, которые раскладывает бот |
| **Живой** | `python3 server.py` | парсинг almetpt.ru на лету |

## Возможности

### Расписание
- Курс → группа → день. 80+ групп, поиск по всем курсам сразу, избранные группы
  (Shift-клик или долгое нажатие по карточке группы).
- Пары с временем, длительностью, аудиторией (или «on-line»), преподавателем,
  темой занятия и домашним заданием.
- **Пары по подгруппам показываются отдельными блоками** — у каждой подгруппы
  своя аудитория, свой преподаватель, своя тема и своя домашка.
- **Выбор своей подгруппы** (1 или 2). Сайт запоминает её и показывает только
  ваши занятия: у общей пары остаётся ваша половина, а пара, которой у вашей
  подгруппы нет, исчезает из расписания. Фильтр действует и на обзор недели,
  и на список домашних заданий, и на выгрузку в календарь.
- Пометка **замен**, предупреждение «основное расписание отсутствует».
- Перемены и «окна» между парами с подсчётом длительности.
- Консультации преподавателей и график учебного процесса на год
  (текущий период подсвечен).

### Живой режим дня
- Текущая пара подсвечена, прогресс-бар, обратный отсчёт до конца пары
  или до начала следующей.
- Панель «что сейчас» над расписанием.
- Всё время считается **по Москве** через `Intl.DateTimeFormat`, независимо
  от часового пояса устройства.

### Навигация
- Обзор **недели**: все семь дней, количество пар, сводка домашних заданий.
- Полоска недели с точками — сразу видно, где сколько пар.
- Свайпы влево/вправо, стрелки клавиатуры, `Shift+←/→` — ±неделя.
- Ссылки вида `#/1042/2026-10-05` — можно отправить другу.
- Горячие клавиши (`?` — подсказка): `T` сегодня, `W` неделя, `G` группа,
  `F` или `/` поиск, `R` обновить, `D` тема, `E` календарь,
  `1`/`2` своя подгруппа, `0` обе.

### Преподаватели
- Рядом с ФИО — **фотография с сайта техникума** и должность.
  Фото зеркалятся в `docs/data/teachers/<id>.jpg`, поэтому работают офлайн.
  В кружке только фотография: если её нет или она не загрузилась, кружок
  не рисуется вовсе — никаких букв вместо лица.
- Нажатие на ФИО открывает карточку преподавателя: должность, образование,
  стаж и другие поля, которые удалось получить с официальной страницы, плюс
  ссылка на полную карточку на `almetpt.ru`.
- Справочник собирается по id, которые уже есть в разметке расписания
  (`<span class="Staff" data-id=1100>`), и обновляется раз в месяц.

### Фишки
- **Поиск по преподавателю, аудитории, группе и предмету** за любой день:
  «где сейчас Зинкин», «кто в 233-й».
- **Экспорт в календарь (.ics)** — день или вся неделя, с темой, аудиторией
  и преподавателем; время в UTC, импортируется куда угодно.
- **Копирование домашних заданий** одной кнопкой — списком, с датами и
  правильной привязкой к подгруппе.
- **PWA**: устанавливается на телефон, работает офлайн (service worker кэширует
  оболочку и данные), ярлыки «Сегодня» / «Неделя».
- Баннер, если зеркало давно не обновлялось, со ссылкой на оригинальный сайт.
- Светлая/тёмная тема (авто по системе), запоминание группы, курса и режима.
- Широкий макет в одну колонку: расписание занимает всю ширину страницы,
  а управление (дата, неделя, режим, группа) стоит над ним одной строкой.
  Пары по подгруппам на широком экране встают рядом, а не друг под другом.
- **Телефон как основной экран**: свайп влево-вправо листает дни, колонка
  времени ужимается, ФИО переносится вместо многоточия, список групп
  прокручивается внутри себя, выбор подгруппы стоит над ним, поля ввода
  в 16px (иначе iOS зазумит страницу), крупные зоны нажатия и учёт
  safe-area под вырезом.

### Почему не всё помечено «заменой»

На сайте техникума день складывается из **основного расписания** и
**таблицы замен**. У АПТ основное расписание в большинстве дней не
выкладывается вообще — весь день публикуется через таблицу замен, поэтому
класс `changesPair` стоит на каждой паре (проверено на живой странице:
1640 из 1641 пары). Значок, который горит всегда, ничего не сообщает,
поэтому здесь он показывается только когда заменена **часть** пар дня.
Если весь день пришёл из таблицы замен, отдельная кнопка и лишнее пояснение
не показываются — расписание остаётся обычным.

## Архитектура

```
apt/
├── parser.py              # мини-DOM + парсеры страниц almetpt.ru
├── fetch_all.py           # бот: almetpt.ru -> docs/data/*.json
├── server.py              # живой режим: HTTP-сервер + прокси-парсер
├── static/                # исходники фронтенда
│   ├── index.html         #   весь интерфейс: разметка, стили, логика
│   ├── sw.js              #   service worker (офлайн)
│   ├── manifest.webmanifest
│   └── icons/
├── docs/                  # то, что раздаёт GitHub Pages (бот обновляет сам)
│   ├── index.html, sw.js, manifest.webmanifest, icons/
│   └── data/
│       ├── groups.json, bells.json, meta.json
      ├── teachers.json          # справочник преподавателей
      ├── teachers/<id>.jpg      # зеркало фотографий
│       ├── summary.json           # сводка «сколько пар» по всем группам
│       ├── checked.json           # журнал проверок (служебный)
│       ├── d/<groupId>/<date>.json
│       └── x/<date>.json          # срез дня по всем группам (для поиска)
├── data/                  # fallback-данные и дисковый кэш живого режима
├── tests/                 # тесты парсера, бота, интеграции, вёрстки и фронтенда
└── tools/                 # генераторы иконок, фикстур, демо-зеркала
    └── update-workflow.yml    # готовый workflow — скопировать в .github/ вручную
```

### Формат дня

```jsonc
{
  "ok": true, "groupId": 1042, "group": "СА-231б",
  "date": "2026-10-05", "dateText": "понедельник, 5 октября 2026 года",
  "published": true,        // расписание на эту дату вообще выложено
  "baseMissing": false,     // «основное расписание отсутствует»
  "pairs": [{
    "n": "I", "num": 1, "start": "08:00", "end": "09:20",
    "room": "233", "roomTitle": "…", "subject": "…", "subjectFull": "…",
    "teacher": "…", "teachers": ["…"], "subgroup": "1 п/гр.",
    "topics": [], "homework": [], "notes": [],
    "changed": false, "variants": 2,
    "parts": [                      // заполняется, когда variants > 1
      { "subgroup": "1 п/гр.", "room": "233", "subject": "…",
        "teacher": "…", "topics": [], "homework": [], "notes": [] }
    ]
  }],
  "consultations": [], "graf": [], "notices": [],
  "fetchedAt": 1791100000, "stale": false
}
```

Плоские поля (`subject`, `teacher`, `room`) остаются для совместимости:
при нескольких подгруппах они склеены через ` · `, а интерфейс берёт `parts[]`.

### API живого режима

| Метод | Ответ |
|---|---|
| `GET /api/health` | проверка живости (по ней фронтенд выбирает режим) |
| `GET /api/groups` | `{ ok, groups:[{id,name,course}], fetchedAt, source }` |
| `GET /api/bells` | время пар |
| `GET /api/schedule?group=ID&date=YYYY-MM-DD` | день целиком (формат выше) |
| `GET /api/lessons?date=YYYY-MM-DD` | срез дня по всем группам — для поиска |

Справочник преподавателей (`data/teachers.json`) в обоих режимах читается
из статики — он меняется редко и не требует живого запроса.

Всё, что не `/api/`, сервер отдаёт как статику из `static/`.

## Запуск

```bash
python3 server.py            # http://localhost:8000
PORT=8080 python3 server.py
```

Зависимостей нет — нужен Python 3.9+.

### Посмотреть интерфейс без доступа к almetpt.ru

```bash
python3 tools/make_demo.py --out /tmp/preview
python3 -m http.server 8080 --directory /tmp/preview
```

`make_demo.py` раскладывает уже сохранённые в `docs/` дни по текущей и
следующей неделе — видно живые состояния («идёт пара», перемены, обзор недели).

### Пересобрать статику и индексы без сети

```bash
python3 fetch_all.py --offline        # static/ -> docs/, пересборка summary.json и x/
```

## Тесты

```bash
python3 -m unittest discover -s tests          # парсер, бот, интеграция, вёрстка (71 тест)
```

Фронтенд тестируется в jsdom — страница реально загружается, `fetch`
подменяется файлами зеркала, после чего проверяется разметка и поведение:

```bash
npm i jsdom                                     # в любой папке
JSDOM_PATH=$PWD/node_modules/.package-lock.json \
  node --test tests/frontend.test.mjs           # 47 тестов
```

Скриншот в CI не снять, поэтому мобильная вёрстка закрыта отдельным
набором `tests/test_css_mobile.py`: он разбирает CSS страницы и проверяет
то, что ломается молча, — колонки шире экрана, жёсткие ширины, размер
шрифта в полях ввода (меньше 16px — и Safari на iOS зазумит страницу),
зоны нажатия и совпадение отступа строки «перемена» с краем карточек.

В `tests/fixtures/raw/` лежат две **настоящие** страницы almetpt.ru
(их снял раннер GitHub Actions) — на них проверяется, что парсер не
разойдётся с живой разметкой.

Фикстуры для фронтенда собираются из синтетических страниц настоящим парсером:

```bash
python3 tools/make_web_fixtures.py
```

Иконки (PNG рисуются без зависимостей, ~1 мин):

```bash
python3 tools/make_icons.py
```

## Бот и GitHub Pages

`fetch_all.py` скачивает группы, звонки и расписание всех групп на окно дат
и складывает в `docs/data/`. Запускается по cron из `.github/workflows/update.yml`.

Готовый workflow лежит в `tools/update-workflow.yml`. Его нужно
**скопировать руками** — GitHub запрещает приложениям без права `workflows`
писать в `.github/workflows/`, поэтому файл и хранится в стороне:

```bash
cp tools/update-workflow.yml .github/workflows/update.yml
git add .github/workflows/update.yml
git commit -m "обновление расписания по расписанию"
git push
```

Что в нём: запуск каждые полчаса и по кнопке, прогон тестов перед записью
данных, окно в две недели в шесть потоков, коммит только при реальных
изменениях и повтор `pull --rebase && push` на случай гонки.

```bash
python3 fetch_all.py --weeks 2 --workers 6     # текущая + следующая неделя
python3 fetch_all.py --days=-2..7              # произвольное окно
python3 fetch_all.py --full                    # игнорировать TTL, перекачать всё
python3 fetch_all.py --keep-days 14            # сколько дней хранить
```

### Почему раньше было «пар нет»

Старый бот определял свежесть файла по времени его изменения на диске.
После `actions/checkout` у всех файлов время = момент клонирования, поэтому
«свежими» считались вообще все. Каждая дата скачивалась ровно один раз —
за трое суток до занятий, когда техникум расписание ещё не выложил, — и
навсегда оставалась в зеркале как `published: false, pairs: []`.

Сейчас:

- Время последней проверки хранится в `docs/data/checked.json`, а не берётся
  с файловой системы.
- TTL зависит от даты:

  | Дата | Перепроверять |
  |---|---|
  | сегодня | 10 мин |
  | +1…+3 дня | 10 мин |
  | дальше | 3 ч |
  | прошедшая, опубликованная, с парами | 7 дней |
  | прошедшая прочая | 12 ч |

- Файл дня перезаписывается **только если содержимое изменилось**, поэтому
  бот не создаёт по 500 «пустых» коммитов. Индексы (`summary.json`, `x/*.json`)
  тоже пишутся через сравнение содержимого и не содержат меток времени.

### Нюансы

- **Cron в Actions не точный**: запуск может немного опоздать из-за очереди GitHub,
  но бот проверяет ближайшие даты каждые 10 минут — это особенно важно в 12–14 МСК,
  когда обычно появляется расписание на завтра.
- Запросы идут из дата-центров GitHub. Если almetpt.ru начнёт резать
  иностранные IP — помогает self-hosted раннер или живой `server.py`.
- Даты вне окна сборки показывают честное «за эту дату данных нет».
- Если сайт техникума недоступен, бот оставляет старые данные, а сайт
  показывает баннер «зеркало давно не обновлялось».
